Source-grounded architecture review

A durable agent turn loop, built as a worker mesh coordinator.

Harness persists messages, assembles model context, streams completions, enforces function policy, checkpoints calls, and repeats as resumable queue steps. It deliberately owns sequencing—not transcripts, context storage, model providers, or arbitrary business logic.

The durable turn loop

src/turn_loop.rs is the core. A queue delivery runs one step, not the entire conversation. At-least-once delivery is made safe with monotonic steps, stale guards, deterministic transcript IDs, and per-call checkpoints.

Step lifecycle

  1. Acquire the per-session lock and load the authoritative TurnRecord.
  2. Drop stale, wrong-turn, or already-terminal deliveries.
  3. Observe cancellation and execute first-step hooks.
  4. Drain steering messages, assemble context, expose allowed tools.
  5. Reserve hard budget, stream router::chat, and coalesce partial transcript updates.
  6. Persist assistant output; plan and checkpoint function calls.
  7. Dispatch calls or park held calls; append deterministic results.
  8. Advance and enqueue another step, or finalize and emit completion.

Turn states

runningawaiting_functionscompletedcancelledfailed

A terminal status ends this turn, but not always the logical run. If the session owns an armed one-shot wake, turn-completed carries terminal: false; a later notification starts the continuation turn.

Crash-safety mechanisms

  • Step number rejects queue redelivery.
  • Call states: triggered → pending/done.
  • Deterministic entry IDs make transcript appends idempotent.
  • Next-step enqueue retries 5 times across registry restart windows.
  • Durable abort is re-read after generation to close a cancellation race.

State and recovery model

The persisted turn record is the recovery snapshot. The code explicitly refuses to reconstruct a turn from transcript alone because policy, budgets, output contracts, parent linkage, and checkpoints would be lost.

Security and authority

The security posture is structural and fail-closed. The model cannot gain reach merely through prompt instructions, and trigger-fired work cannot bypass human approval expectations.

Dispatch policy

A call is allowed only if it matches an allow glob and no deny glob. Missing or empty allow denies everything. Discovery list/info responses are filtered through the same policy.

Agent trigger wrapper

Default exposure gives the model one agent_trigger tool with {function, description, payload}. Native exposure can publish individual schemas. Truncated argument markers are evidence only and never execute.

Filesystem scope

The turn stamps a trusted metadata.fs_scope.root. Spawned children inherit it unless explicitly given another absolute root. Session grants and one-shot grants are unioned at dispatch.

Trigger authority interception

Agent calls to engine::register_trigger are intercepted. The harness stamps the owner, freezes the registrant’s policy, checks unattended approval, validates conditions, and points the engine only at one internal delivery function. Engine metadata contains merely {"__binding":"…"}.

Defense details

  • Private state namespace claims cannot be laundered by agents.
  • harness::* cannot be a mechanical binding target.
  • Turn-event trigger types are not agent-bindable, avoiding self-wake loops.
  • Approval checks fail closed except when the approval worker is genuinely absent.
  • Child policy is a subset; deny rules union and therefore propagate.

Sub-agent design

Children are normal harness turns in child sessions. Delegation is intentionally one-way: spawn returns identifiers, never the result or failure.

Lifecycle and limits

  • Default depth limit: 3.
  • Default fan-out: 8 per parent turn.
  • Requested tool policy can narrow but cannot exceed the parent.
  • Child max turns is capped by the parent’s remaining turn budget.
  • Token/cost execution ledger is shared with the root.
  • Named-session reuse is confined to the caller’s own tree.

Leaf capability wall

Unless options.orchestrator: true, child denies gain:

harness::spawn harness::send engine::register_trigger engine::unregister_trigger engine::registered-triggers::*

Narrow non-empty child policies automatically retain contract discovery (engine::functions::list/info). Outcomes must be written to a named shared medium and observed there.

Key design principle: the parent owns the control plane; children perform assignments and write the medium; the medium wakes the parent.

Reactive triggers and durable bindings

Every agent registration is normalized into one binding record and one delivery hop. Wakes inject a message into the owner session. Mechanical bindings call an allowed plain function and discard its result.

provider event ↓ harness::trigger::deliver ├─ resolve durable binding ├─ safety gates + declared conditions ├─ atomic lifecycle claim ├─ inject event into payload template ├─ dispatch under frozen capability └─ record delivery / retire if spent

Wake shape

Omit function_id. Default once: true. It is the only binding shape that can reach the session. A lifecycle expiry wakes the owner with an explicit “nothing fired” notice.

Call shape

Name a non-harness target plus metadata.payload and event_into. Default is standing, so lifecycle bounds or explicit teardown are important.

Conditions

Ordered ordinary functions return allow|skip, optional replacement payload, and reason. Errors skip visibly. state::barrier implements fan-in.

Delivery semantics: claims are at-most-once after the event reaches the harness, but the engine’s fire-and-forget path has no retry/outbox. A crash before claim can lose the event; exactly-once is explicitly out of scope.

Context, output contracts, and budgets

Context pipeline

The loop reserves provider framing and hook headroom, asks context-manager to assemble/compact, then tracks the final request by system prompt, tools, role-based messages, overhead, and hook guidance. Provider token counters exactify stable categories when available.

Snapshot stores usable / total / free, estimator, compaction, usage, and running session cost.

Output contracts

Text is direct. JSON uses provider-native structured output if the catalog reports support; otherwise harness attaches a synthetic submit_result tool. Optional JSON Schema validation retries up to the configured limit before best-effort finalization.

Hard execution budget

A root-and-child tree shares token and USD limits. Each generation reserves worst-case input + output before provider spend, then reconciles with actual usage. Missing/partial usage consumes the full reservation.

Cost enforcement

Cost caps require model catalog pricing. The reservation chooses the most expensive configured input class, including cache classes. Missing or invalid pricing fails closed rather than silently running unmetered.

Boot and runtime configuration

Startup order is intentionally load-bearing. Trigger types exist before functions capture subscriber sets; discovery is ready before queue restoration can release old jobs; readiness is emitted last.

1. parse CLI and optional seed YAML 2. connect worker to engine WebSocket 3. register configuration schema; fetch authoritative value 4. register event + hook trigger types 5. seed function registry cache; bind availability updates 6. register harness functions and injected console UI 7. register timer trigger type 8. ensure dedicated harness-turn queue 9. bind sweep + session-deleted lifecycle triggers 10. bind configuration change handler LAST 11. emit harness::ready; run binding GC + expiry sweep

Configuration is hot-reloaded. Numeric/time settings are read from a live snapshot; changing the structural cron expression rebinds the sweep. Defaults observed in code include 500 turns, 3 depth, 8 children, 3 transient resumes, 150 ms stream coalescing, and a daily midnight sweep.

Engineering findings

Strong: explicit invariants

Comments and tests pin subtle races: post-generation cancellation, fast one-shot firing before registration returns, queue/finalize windows, CAS fire claims, and child-session collisions.

Strong: authority boundaries

Policy-filtered discovery, frozen binding capability, owner-scoped unregister, approval probes, private state namespaces, and leaf sub-agents form a coherent defense-in-depth story.

Strong: operational visibility

Trace tagging, hidden plumbing spans, context snapshots, metrics, queued-message events, trigger fire records, and explicit expiry notices target real debugging failures.

Risk: central loop size

turn_loop.rs is over 120 KB and functions/subscribe.rs over 77 KB. Their responsibilities are well documented but change coupling and review load are intrinsically high.

Risk: distributed durability

Correctness spans queue, state, session, router, and engine trigger behavior. Some guarantees are deliberately at-most-once, and durable claims are only as persistent as the state adapter.

Risk: mixed historical paths

Deferred resolution retains legacy pre-fire-and-forget child support. Compatibility is sensible, but old and new semantics increase the number of lifecycle paths maintainers must reason about.

Overall: the implementation is unusually candid about its guarantees and failure boundaries. Its complexity comes primarily from making a distributed model/tool loop resumable, policy-aware, observable, and safely reactive—not from ornamental abstraction.
