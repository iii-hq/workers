# Changelog

## 0.1.0

- First release: the **ultracode** orchestrator, the hidden **ultracode-lead** that runs one ticket through its phases, the **ultracode-worker** and **ultracode-impl** work tiers, and the **ultracode-verifier** and **ultracode-qa** check tiers.
- Kanban tickets are the work queue and the live monitor: run items are subtasks of the run ticket (its progress bar tracks the run), each ticket's assignee picks its work tier, and `project=` / `release=` file the run under an existing project or release.
- One lead per ticket, shown in the session tree as `<KEY> · <title>` with its phases under it. Leads fan out in bounded waves and fan in through one `state::barrier` wake per wave with a deadline; each lead does the same per phase, retries rejected attempts (`attempts=`), and runs verify and review side by side. Bounded rounds, a completeness critic and an optional soft budget.
- The dev flow, switched on for code goals in a git repository (`flow=auto`): the [superpowers](https://github.com/obra/superpowers) way. Design and plan approved through `harness::ask` (`approve=on`), test-first tickets (`Files`, `Test first`, `Implement`, `Verify`, `Commit`), one git worktree per run with one commit per ticket, a code review of every commit, a branch review (full suite, linter, whole diff), loose ends filed as `pending` Backlog subtasks, and a finish you choose: merge, PR, keep or discard.
- Each profile preloads the contracts of the functions its role calls on every run (orchestrator: kanban, state, harness spawn/status/stop/metrics/ask, shell and tree; lead: spawn, triggers and state; work tiers: `shell::exec`, `coder::read-file`, plus `coder::create-file` / `coder::update-file` for `ultracode-impl`; check tiers: `state::get`, `shell::exec`).
- Lean context: the orchestrator and leads start without the skills index (`skills_index: false`), ask for compact kanban writes and context-free `harness::metrics`, and phase sub-agents drop the index through their deny list. Harness, iii-directory and kanban builds without these options ignore them.
- Requires `harness` `^1.8.53`, `state` `>=0.22.18`, `ide` `>=0.12.0` and `kanban` `^0.1.21` (subtasks, compact writes, `add_labels` / `remove_labels`). Does not use the `workflow` worker.
