# Workers source regression harness

This preview imports the current Workers page and the console's real UI primitives, styles, Monaco editor, command registry, and keyboard dispatcher. It replaces the backend selector and iii client with deterministic, in-memory fixtures. The Vite configuration has no engine or console proxies. HMR and its development socket are disabled; because Vite 8.1.5 still injects a connecting client, the harness serves only its CSS style helpers in place of that transport. Every browser test checks that no WebSocket was opened.

Run from the repository root:

```sh
pnpm --dir ade/web test:e2e:workers
```

CI runs this suite in its own `run Workers settings Playwright` job of the Harness integration workflow. It needs no stack bundle, so it starts alongside the stack build instead of after it, and keeps failure traces in the `workers-settings-e2e-artifacts` artifact.

Playwright builds the harness into `target/workers-harness-dist` and serves that production bundle with `vite preview` on port 4180: an unbundled development page costs about four seconds of CPU per load, a built one about one. It reuses a harness already running on that port, and stops a server it started when the run finishes. For a persistent manual preview with the development server:

```sh
pnpm --dir ade/web exec vite --config e2e/workers-harness/vite.config.ts
```

The persistent preview binds `0.0.0.0:4180`. On the current LAN, open [the Workers preview](http://192.168.1.206:4180/); the root URL redirects to `/e2e/workers-harness/index.html` and preserves query parameters. This preview uses the same in-memory backend and does not connect to the live engine. Keep the manual Vite process running while the preview is needed.

Open `/e2e/workers-harness/index.html` on that server. The `theme=dark` or `theme=light` query controls theme. `pane=720` constrains the hosting pane inside a wider viewport. `commands=1` enables the real Workers command registration and pane keyboard dispatch. `package=ade` declares that fixture as a package to exercise the separate restart. `loadFailures=1` fails its first declaration read. `specialWorkers=1` adds `constructor`, `toString`, and `__proto__` declarations. `stoppedWorkers=1` reports `state` and `storage` as stopped to exercise the native stopped-worker Save confirmation without a lifecycle mutation. `cycleWorkers=1` gives `ade` no dependencies, `state` a dependency on `ade`, and `storage` a dependency on `state`, exposing direct and transitive cycle-producing choices. The default selection is the project overview; select `ade` and its Settings tab with normal clicks.

The fixture exposes `window.__WORKERS_HARNESS__` for assertions. `calls` records every mocked RPC. Set `saveMode` to `error` to simulate a failed write, `restart-error` to write the entry and fail its compose restart, or `reload-error` to write successfully and reject subsequent declaration reads. `saveDelay` and `readDelay` control pending saves and reads in milliseconds. `restartMode=error` fails a package restart; `snapshotMode=error` fails runtime reads. Successful edits apply only to the in-memory entry and return a completed compose operation under the caller's operation ID. Secret values remain masked in declaration reads.

`externalEdit(name, { run, config_override, start_after, environment })` simulates another client editing a stored declaration. An optional `environment` array also exercises removal of a stored key while a local secret replacement is pending. `runCommand('refresh')` invokes the real registered page command; `readsCompleted` distinguishes pending and completed declaration reads for race checks.
