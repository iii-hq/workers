# shadcn/ui components (Base UI)

Generated by the shadcn CLI, Base UI flavour (`components.json`: style
`base-nova`, base colour neutral, Lucide icons). These are the console's
components: a screen reaches for them first, and `components/ui` keeps only
the console's own compositions (a page shell, a tree row, the adaptive
mobile sheet) plus thin wrappers that hand the same parts to worker UIs
under the first `@iii-dev/console-ui` names (`Button`, `Dialog`, `Tabs`,
`DropdownMenu`, `Tooltip`, `Badge`, `Input`, `Kbd`, …).

Add a component from `ade/web`:

```sh
npx shadcn@latest add <name> -y
npx biome check --write src/components/shadcn
```

Never pass `-o` (overwrite): `button.tsx`, `toggle.tsx` and `separator.tsx`
carry console adjustments (the three action looks, the toolbar sizes).

- Files land here, not in `components/ui`: the CLI writes lowercase names
  (`button.tsx`) and the console's own `Button.tsx` lives next door on a
  case-insensitive filesystem.
- The semantic variables these components read (`--background`,
  `--popover`, `--primary`, `--muted`, `--border`, `--ring`, `--radius`,
  the shadow and tracking scales) ARE the design system: they are defined
  at the top of `src/index.css` in oklch, light on `:root` and dark on
  `.dark` / `[data-theme="dark"]`. Every console token (`--color-ink`,
  `--color-surface`, `--color-edge`, …) is an alias onto one of them.
- Fonts and radius come from the same variables: Inter (`--font-sans`),
  Geist Mono (`--font-mono`), `--radius: 0.9rem` with the sm/md/lg/xl steps
  off it.
- One deliberate difference from stock shadcn: `--color-accent` is the
  console's primary fill (live state, gauges, primary actions), not the
  hover tint. Hover washes use `muted` (`theme-hover-conformance.test.ts`).
- A component that needs a console behaviour (a worker's CSS scope on a
  portal, a panel as the collision boundary) gets it here, in the vendored
  copy, with a comment saying why.
