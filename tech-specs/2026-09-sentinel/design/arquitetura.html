Arquitetura do Sentinel

Um worker que assina a telemetria do engine, agrupa as falhas por causa provável, congela a evidência antes que o store em memória a descarte, e abre investigações assistidas no harness. Três partes: a arquitetura — o que ele liga e o que o agente alcança; os fluxos — do tick ao grupo, do log ao span, do clique ao diagnóstico, e o ciclo de vida que só o humano fecha; e os schemas — as nove tabelas, os tipos de wire e a configuração.

parte I

Arquitetura

Onde o Sentinel fica, o que ele consome, o que ele chama — e a única fronteira de segurança que existe: a lista de allow da sessão, porque não há gate e a permissão é sempre full.

fig. 1

Mapa do sistema

O Sentinel fica entre o engine e o harness e nunca fala com um provedor de modelo direto. Ele também é um worker: seus próprios spans entram pelo mesmo OTLP que os de todos — as faixas laranja marcam os cortes que impedem isso de virar um laço, e o que impede um segredo de sair.

fig. 2

O que a sessão alcança

Não há gate: nenhuma chamada do agente espera aprovação. Por isso a lista de allow é o modelo de permissão inteiro — o que está nela roda, o que não está é recusado antes de sair, e o deny vence qualquer allow (policy.rs:112).

parte II

Fluxos

Cinco caminhos. Três são do worker sozinho — o tick que vira grupo, o log que espera pelo span, o ponto de decisão que sempre tem fallback. Dois são com gente: a investigação assistida e o ciclo de vida do grupo, que nenhum modelo fecha.

fig. 3

Ingest — de um tick a um grupo

Treze estágios, todos determinísticos. Onde há um losango, o tier de decisões pode substituir a heurística — e a heurística escrita na caixa é o fallback, sempre. A redação corre antes do primeiro INSERT: nada cru chega ao banco.

fig. 4

Log ERROR — espera pelo span

Logs chegam antes do span que os explica — o log é emitido dentro do handler, o span fecha depois. Um log ERROR nunca vira grupo na hora: fica como uma linha sem grupo, e o schema só admite isso enquanto ele espera.

fig. 5

Investigação assistida

Nenhum turno tem contrato de saída: o usuário intervém e é respondido em prosa. O DiagnosisV1 nasce quando o agente chama sentinel::diagnosis::record de dentro da sessão — a única escrita que ele pode fazer, validada pelo schema da função, uma versão por chamada. A coluna ao lado é uma vista da investigação, não a investigação.

fig. 6

Ciclo de vida do grupo

Seis estados. As setas verdes são decisões humanas; as laranja são o registro do agente; as pretas, o próprio ingest. Um registro só avança investigating ou new — nunca desfaz o que uma pessoa decidiu.

fig. 7

Um ponto de decisão

O tier de decisões não acrescenta funcionalidade: troca uma constante afinada na mão por uma decisão calibrada, com a heurística sempre atrás. É o mesmo caminho para os nove pontos; o que muda por ponto é o limiar e o modo — agir, propor ou só exibir.

parte III

Schemas de dados

Um database (SQLite primary, zero-config), nove tabelas, e os tipos que atravessam o wire: o evento normalizado, o bundle congelado, o diagnóstico que o agente grava, a decisão que o tier persiste. Tudo que chega ao banco já passou pelo redator.

fig. 8

Modelo de dados

O grupo é o eixo; o fingerprint é a identidade e nunca é recalculado por um modelo — o tier de decisões só escreve nas duas tabelas tracejadas.

tipos de wire

O que atravessa as fronteiras

Quatro tipos versionados e os contratos das funções que importam. Todo texto neles já está redigido quando sai do ingest; o agente só vê o que o redator deixou.

ErrorEvent

o que um adapter produz — agnóstico de fonte
type ErrorSource = "trace" | "log" | "harness-turn" | "report";

type ErrorEvent = {
  source: ErrorSource;
  dedupe_key: string;        // único por evento físico
  at_ms: number;
  namespace: string;         // "default" · "?" quando namespace_ambiguous
  service_name: string;      // worker DONO do function_id, não o do span
  function_id?: string;
  span_name?: string;
  exception_type?: string;
  // exception.message ?? status_description ?? body — já redigida
  message: string;
  stacktrace?: string;
  trace_id?: string; span_id?: string;
  session_id?: string;       // trace_tags["iii.session.id"]
  turn_id?: string;          // trace_tags["iii.message.id"]
  worker_version?: string;   // engine::workers::list no ingest
  // filtrados por chave, redigidos por valor
  attributes: Record<string, string>;
};

// fingerprint (determinístico, custo zero)
trace: [namespace, owner_worker, function_id ?? span_name,
        exception_type ?? "", normalize(message)]
log:   [namespace, service_name,
        code.function ?? target ?? scope ?? "", "", normalize(message)]
hex(sha256(source ⊕ 0x1f ⊕ key.join(0x1f)))[0..32]

DiagnosisV1

o que o agente grava com sentinel::diagnosis::record
type DiagnosisV1 = {
  summary: string;                 // 1–3 frases, para o humano
  category: "bug" | "configuration" | "dependency"
          | "transient" | "expected" | "unknown";
  confidence: "high" | "medium" | "low";
  root_cause: {
    description: string;
    evidence: Array<{
      kind: "code" | "trace" | "log";
      path?: string; line?: number;  // code — relativo ao repositório
      span_id?: string;              // trace
      excerpt: string;               // ≤ 400 chars
      why: string;
    }>;
  };
  proposed_fix?: {
    description: string; files: string[];
    risk: "low" | "medium" | "high"; steps: string[];
  };
  reproduction?: string;
  missing_evidence?: string[];     // o que faltou para subir a confiança
  version_note?: string;           // deriva entre checkout e versão que falhou
  related_groups?: string[];       // sugestão; o Sentinel não funde por isso
};

// a função — a única escrita da sessão
type DiagnosisRecordRequest  = { group_id: string; diagnosis: DiagnosisV1 };
  // sem investigation_id: a identidade vem da baggage (iii.session.id)
type DiagnosisRecordResponse = {
  diagnosis_id: string;
  version: number;                 // 1 na primeira gravação da investigação
  group_status: GroupStatus;       // diagnosed a partir de investigating/new;
                                   // resolved, ignored e regressed ficam
};
// erros: sentinel/no_investigation — sem baggage, ou a sessão não é investigação
//        sentinel/not_this_group   — a investigação da sessão é de outro grupo

DecisionV1

o que o tier persiste — nunca recalculado
type DecisionPoint =
  | "origin_span" | "log_join" | "group_membership" | "group_merge"
  | "evidence_retention" | "evidence_pruning"
  | "triage" | "investigation_preflight" | "diagnosis_verification";

type DecisionV1<T> = {
  point: DecisionPoint;
  value: T | null;          // null = abaixo do limiar; a heurística decidiu
  confidence: number;       // 0..1, calibrada
  fell_back: boolean;       // limiar, timeout, erro ou tier off
  model?: string;
  at_ms: number;
};

// modos, por ponto
auto     → origin_span · log_join · evidence_retention
           evidence_pruning · investigation_preflight
proposal → group_membership · group_merge · triage (auto-ignore)
display  → diagnosis_verification

// decisões humanas
type ResolveRequest = { group_id: string; until_version_change?: boolean };
type IgnoreRule =
  | { kind: "forever" }
  | { kind: "occurrences"; count: number }
  | { kind: "version_change" };

// evento para irmãos — coalescido por grupo em 1 s
type GroupChanged = {
  op: "created" | "occurrence" | "status";

  occurrence_count: number;
  reason?: "regression" | "ignore_expired" | "resolved"

invariantes

O que não muda em nenhuma configuração

  • captura

    A evidência congela no ingest, nunca na ação. O store do engine é um anel de 10 000 spans; quando alguém clica, o trace já pode ter ido.

  • segredos

    Nada cru chega ao banco nem a um modelo. Todo valor é redigido na captura; o agente só alcança o engine vivo pelos proxies que aplicam o mesmo redator. O system prompt é a terceira barreira, não a primeira.

  • identidade

    O fingerprint é determinístico e nenhum modelo o recalcula. Fusão é uma aresta persistida; colisão é uma dúvida marcada; ambiguidade de namespace fica visível em "?" — o histórico nunca oscila.

  • laço

    O Sentinel nunca ingere a si mesmo: traces cuja raiz é dele e sessões sentinel-inv-* caem antes de qualquer outra regra. O ingest tem breaker; nenhum handler emite ERROR.

  • sessão

    kind: automation nos dois modos, gravado na criação e imutável. A coluna é uma vista: fechá-la não para nada. A identidade da sessão vem da baggage, nunca do payload.

  • registro

    Só sentinel::diagnosis::record produz um DiagnosisV1 — a única escrita do agente, para o grupo que a sessão investiga. Nenhum turno tem contrato de saída; o humano intervém e é respondido em prosa.

  • decisão humana

    Só o humano resolve, ignora ou funde. Um registro avança investigating/new para diagnosed e nada mais; resolved, ignored e regressed ficam como estavam.

  • tiers

    Todo tier de modelo é opcional e desligado por padrão. Sem o harness, o monitor inteiro funciona — só o botão Investigar some. Sem o tier de decisões, cada ponto usa a heurística escrita na spec.
